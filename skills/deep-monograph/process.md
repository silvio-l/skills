# The Sixteen-Phase Pipeline

Work these phases in this logical order. Each phase links to the file that details how to execute it — this file is the backbone, not a duplicate of that detail.

## Phase 1 — Analyze the assignment

Determine: the investigation subject, the central leading question, the desired reader outcome, the target audience, the span of prior knowledge to accommodate, private application scenarios, deliberate exclusions, currency requirements, and the relevant decision situations the reader will face. This should already be settled by the `clarification.md` confirm-and-wait gate — this phase is where you translate that confirmed understanding into working assumptions for the rest of the pipeline.

## Phase 2 — Decompose the topic

Build, internally: main questions, sub-questions, necessary fundamentals, relevant technical terms, technical components, dependencies, variants, risks, counter-positions, practice questions, and likely misunderstandings. This decomposition drives the research plan (Phase 4) and later the outline (Phase 8).

## Phase 3 — Evaluate supplied source material

Analyze everything the user supplied — completely and systematically. Extract core statements, theses, factual claims, examples, argument lines, open questions, contradictions, recognizable interests, possible advertising, and claims that need independent verification. See `research-and-sources.md` for how to weigh and use supplied sources, and its dedicated section for video/audio sources specifically.

## Phase 4 — Build the research plan

Determine which questions must be answered with primary sources, which claims must be currently verified, which practical experience is relevant, which counter-positions must be considered, which source type fits which kind of claim, and which knowledge gaps exist. See `research-and-sources.md` §Source hierarchy.

## Phase 5 — Research

Research broadly first for orientation, then specifically for depth, in cycles — typically three, more only if central questions remain open or essential claims are insufficiently substantiated. The cycle shape and the saturation criteria that decide when to stop are in `research-and-sources.md` §Adaptive research saturation.

## Phase 6 — Structure the evidence

Assign important claims to their supporting sources. Separate verified findings, manufacturer claims, experience values, plausible inferences, and editorial recommendations into distinct statement types. See `research-and-sources.md` §Evidence matrix and §Statement types.

## Phase 7 — Build the mental overall model

Build a technically contradiction-free overall model of the topic. Check explicitly whether all important components, processes, dependencies, and limits are actually understood — not just individually correct, but consistent with each other.

## Phase 8 — Design the dramaturgy and outline

Develop a chapter structure that fits this specific topic, with a recognizable throughline — not a generic template applied unchanged to every subject. See `didactics-and-writing.md` §Adaptive outline and §Chapter architecture.

**In agentic workspace mode**, this phase ends with a second hard gate: present the outline and wait for explicit user approval before Phase 9 begins — a wrong structural cut here wastes the entire draft. See `clarification.md` §Step 4 for how this gate relates to the initial confirm-and-wait gate. Single-response mode has no equivalent pause; finalize the outline internally and continue straight to Phase 9.

## Phase 9 — Write

Write the chapters or the whole work completely, but under control — not as an unstructured stream. Keep terminology, examples, assumptions, and evaluation criteria consistent across the whole work. Apply the explanatory contract, terminology introduction rules, and writing-style rules from `didactics-and-writing.md` throughout.

## Phase 10 — Check facts and sources

Check numbers, units, quotes, currency, contradictions, and source attribution. See `quality-and-output.md` §Fact and source review.

## Phase 11 — Technical review

Check technical correctness, completeness, prerequisites, dependencies, and failure cases. See `quality-and-output.md` §Technical review.

## Phase 12 — Critical counter-check

Actively hunt for weaknesses instead of confirming the work: hidden assumptions, counterexamples, overlooked disadvantages, one-sided source selection, marketing language passed off as fact, overgeneralizations, false certainty, and correlation presented as causation. See `quality-and-output.md` §Critical counter-check.

## Phase 13 — Didactic review

Check, separately for an interested beginner and an advanced home user, whether the reader can actually build a coherent overall picture from what was written. See `quality-and-output.md` §Didactic review, and the per-chapter comprehension check in `didactics-and-writing.md` §Explanatory contract.

## Phase 14 — Practice review

Check transferability to realistic private conditions — budget, time, maintenance, safety. See `quality-and-output.md` §Practice review.

## Phase 15 — Final editing

Improve dramaturgy, transitions, comprehensibility, precision, and language flow. Remove repetition and filler. Run at most three full revision cycles, each fixing concrete deficiencies — don't repeat a full pass with no expected new yield. See `quality-and-output.md` §Final editing.

## Phase 16 — Produce the final artifact

Assemble the complete work plus whatever additional materials the chosen mode calls for. See `quality-and-output.md` §Output format for the single-response vs. workspace-mode deliverable shapes.
